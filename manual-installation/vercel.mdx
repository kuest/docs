<Info>
This is the recommended path for most operators. It matches the same Vercel and Supabase stack used by the guided `/launch` flow.
</Info>

## Before you start

- Review [Environment Variables](/configuration/environment-variables).
- If you are using the guided flow, pre-read [Launch Overview](/launch/overview).

## Manual deploy flow

<Steps>
  <Step title="Prepare the repository">
    Add the codebase to your GitHub account so Vercel can import it. If you are using `/launch`, that GitHub step is already covered in [Launch Overview](/launch/overview).
  </Step>
  <Step title="Set the shared environment variables">
    Start from `.env.example` and fill the base values documented in [Environment Variables](/configuration/environment-variables).
  </Step>
  <Step title="Create the Vercel project">
    In Vercel, create a new project from your GitHub repository and import the environment variables. Keep the repository's `vercel.json`: it selects Bun and runs `bun run db:push && bun run build`.
  </Step>
  <Step title="Attach Supabase">
    Connect your Supabase project through Vercel Storage or configure its connection values manually. Before the production deployment, verify that `POSTGRES_URL`, `SUPABASE_URL`, and `SUPABASE_SECRET_KEY` are available to the project. `SUPABASE_SERVICE_ROLE_KEY` is accepted for existing integrations. Add `POSTGRES_URL_NON_POOLING` with a direct or session-pooler connection if the runtime URL uses transaction pooling.
  </Step>
  <Step title="Deploy and finish setup">
    Set the final `SITE_URL` and configure `CHAIN_ID` for the intended network, then deploy. Confirm that the migration step applied successfully. Open [General](/admin/general) to set company name, branding, fee wallet, and support links.
  </Step>
</Steps>

## What you still need after deploy

- Confirm the admin wallet can sign in.
- Verify that asset uploads work and the uploaded images display on the site.
- Confirm migration logs show the database sync jobs were created. If `pg_cron` or `pg_net` is unavailable, configure [Scheduled Jobs](/manual-installation/scheduler-jobs).
- Review [Theme](/admin/theme), [Locales](/admin/locales), and [Categories](/admin/categories).

<Check>
If you want the same experience but without doing the setup manually, use the guided `/launch` flow and keep [Launch Overview](/launch/overview) open while filling it.
