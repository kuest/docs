The endpoints below return JSON. Send JSON request bodies to `POST /prepare-auth`, `POST /tx-confirm`, and `POST /finalize`; `POST /prepare` receives `multipart/form-data`.

Set the worker URL once so the examples work with the Kuest endpoint or an operator runtime override:

```bash
export CREATE_MARKET_URL=https://create-market.kuest.com
```

API errors use this shape (a rejected CORS origin returns plain-text `Forbidden`):

```json
{
  "error": {
    "code": "validation_error",
    "message": "requestId is invalid",
    "details": null
  }
}
```

## 1. GET /market-config

Reads runtime configuration for the worker.

```bash
curl "${CREATE_MARKET_URL}/market-config"
```

Use this response to choose the chain, validate images, display required funding, and know which contracts the returned transaction plan will target.

Important fields:

| Field | Meaning |
| --- | --- |
| `defaultChainId` | Chain used when `payload.chainId` is omitted. |
| `defaultResolutionType` | Default resolution stack, usually `dro_moov2`. |
| `supportedChainIds` | Chain IDs accepted by the worker. |
| `requiredCreatorFundingUsdc` | Per-market funding hint for the default resolution type, not the total for a multi-market event. |
| `directNormalMarketFeeUsdc` | Direct resolution fee for normal markets. |
| `directNegRiskQuestionFeeUsdc` | Direct resolution fee per negative-risk question. |
| `resolutionRewards` | Resolution Rewards proxy address. |
| `imagePolicy` | Upload and normalized image limits. |
| `chains` | Per-chain contract addresses and resolution stacks. |

Budget for every market: `multi_multiple` pays the standard fee for each independent market, while `multi_unique` pays the neg-risk fee for each question. Inspect the returned transaction plan before signing; include POL for gas separately.

## 2. POST /prepare-auth

Creates a short-lived EIP-712 challenge for the exact payload hash.

```json
{
  "creator": "0x1111111111111111111111111111111111111111",
  "chainId": 80002,
  "payloadHash": "0xaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

Response:

```json
{
  "requestId": "8b583ebd-1f8f-46fa-b31b-06643f58d457",
  "nonce": "0xbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "expiresAt": 1846000000000,
  "creator": "0x1111111111111111111111111111111111111111",
  "chainId": 80002,
  "payloadHash": "0xaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "domain": {
    "name": "Create Market",
    "version": "1",
    "verifyingContract": "0x0000000000000000000000000000000000000000"
  },
  "primaryType": "CreateMarketAuth",
  "types": {
    "CreateMarketAuth": [
      { "name": "requestId", "type": "string" },
      { "name": "creator", "type": "address" },
      { "name": "payloadHash", "type": "bytes32" },
      { "name": "nonce", "type": "bytes32" },
      { "name": "expiresAt", "type": "uint256" },
      { "name": "chainId", "type": "uint256" }
    ]
  }
}
```

`expiresAt` is a Unix timestamp in **milliseconds**, and the challenge is valid for 30 minutes. Use the returned domain and types; include `chainId` in the EIP-712 domain when signing:

```ts
const signature = await walletClient.signTypedData({
  account,
  domain: {
    ...auth.domain,
    chainId: auth.chainId
  },
  types: auth.types,
  primaryType: "CreateMarketAuth",
  message: {
    requestId: auth.requestId,
    creator: auth.creator,
    payloadHash: auth.payloadHash,
    nonce: auth.nonce,
    expiresAt: BigInt(auth.expiresAt),
    chainId: BigInt(auth.chainId)
  }
});
```

## 3. POST /prepare

Validates the signed payload, processes images, uploads draft metadata to Irys, checks for existing initialized questions, and starts background preparation.

Required multipart fields:

| Field | Type | Notes |
| --- | --- | --- |
| `payload` | string | Exact JSON string used to compute `payloadHash`. |
| `auth` | string | JSON string with `requestId`, `nonce`, `expiresAt`, `payloadHash`, and `signature`. |
| `eventImage` | file | Required event image. |
| `optionImage:<optionId>` | file | Optional keyed option image. |
| `optionImages[]` | file | Optional fallback option images by order. |
| `teamLogo:home` / `teamLogo:away` | file | Required for sports teams that do not include `logo` in the payload. |

Save the exact string you hashed as `payload.json`, and save the returned challenge fields plus your real signature as `auth.json`. Do not reformat `payload.json` after hashing it.

```bash
curl -X POST "${CREATE_MARKET_URL}/prepare" \
  -F 'payload=<payload.json' \
  -F 'auth=<auth.json' \
  -F 'eventImage=@./event.webp'
```

Accepted response (`202 Accepted`):

```json
{
  "requestId": "8b583ebd-1f8f-46fa-b31b-06643f58d457",
  "chainId": 80002,
  "creator": "0x1111111111111111111111111111111111111111",
  "status": "prepare_in_progress"
}
```

After this response, poll `GET /pending` until `request.prepared.txPlan` is available.

## 4. GET /pending

Returns a resumable request by `requestId` or the latest resumable request for a creator.

```bash
curl "${CREATE_MARKET_URL}/pending?requestId=8b583ebd-1f8f-46fa-b31b-06643f58d457&creator=0x1111111111111111111111111111111111111111&chainId=80002"
```

Query parameters:

| Parameter | Required | Notes |
| --- | --- | --- |
| `requestId` | No | Recommended once you have it. |
| `creator` | No | Required if `requestId` is omitted. When both are sent, the request must belong to this creator. |
| `chainId` | No | Optional filter. |

If no request matches the supplied identifiers, the response is `{ "request": null }`. Persist `requestId` so recovery targets the intended request instead of whichever request is newest for that creator.

Prepared response shape:

```json

    "payloadHash": "0xaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "status": "prepared",
    "creator": "0x1111111111111111111111111111111111111111",
    "chainId": 80002,
    "expiresAt": 1846000000000,
    "updatedAt": 1845999000000,
    "errorMessage": null,
    "prepared": {
      "requestId": "8b583ebd-1f8f-46fa-b31b-06643f58d457",
      "chainId": 80002,
      "creator": "0x1111111111111111111111111111111111111111",
      "txPlan": [
        {
          "id": "approve-direct-resolution-fee",
          "to": "0x41E94Eb019C0762f9Bfcf9Fb1E58725BfB0e7582",
          "value": "0",
          "data": "0x095ea7b3...",
          "description": "Approve 5 USDC for direct resolution fees"
        },
        {
          "id": "pay-direct-market-fee-1",
          "to": "0x57827d48Da09ba227aFda89C083b4E35972Aa741",
          "value": "0",
          "data": "0x...",
          "description": "Pay direct resolution fee for this market",
          "marketKey": "binary"
        },
        {
          "id": "initialize-market-1",
          "to": "0xc97c5aa5180731c7bB741Fc9B3c293272ca8d33D",
          "value": "0",
          "data": "0x1f7a6ad6...",
          "description": "Initialize market \"Will BTC close above 110000 USD on March 31, 2028?\"",
          "marketKey": "binary"
        }
      ]
    },
    "txs": [],
    "registerResults": [],
    "metadataUpdates": [],
    "metadataUpdateTxPlan": []

```

The example above abbreviates calldata and uses placeholder hashes; always execute the exact plan returned for your request, including fee-payment transactions.

Send each `txPlan` item **in order** from the creator wallet, and wait for a successful receipt before sending a dependent transaction:

```ts
const hash = await walletClient.sendTransaction({
  account: creatorAccount,
  to: tx.to,
  value: BigInt(tx.value),
  data: tx.data
});
const receipt = await publicClient.waitForTransactionReceipt({ hash });
if (receipt.status !== "success") {
  throw new Error(`Transaction ${tx.id} reverted: ${hash}`);
}
```

## 5. POST /tx-confirm

Persists transaction hashes so the flow can resume. This endpoint checks that transaction IDs belong to the saved plan. Final validation of sender, target, calldata, value, and receipt happens during `POST /finalize`.

```json
{
  "requestId": "8b583ebd-1f8f-46fa-b31b-06643f58d457",
  "creator": "0x1111111111111111111111111111111111111111",
  "txs": [
    {
      "id": "approve-direct-resolution-fee",
      "hash": "0xdddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd"
    },
    {
      "id": "pay-direct-market-fee-1",
      "hash": "0x7777777777777777777777777777777777777777777777777777777777777777"
    },
    {
      "id": "initialize-market-1",
      "hash": "0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee"
    }
  ]
}
```

Reusing an ID with the same hash is safe; changing its hash returns `409` with `Conflicting tx hash`. The `prepared` status in this endpoint's response acknowledges saved hashes; use `GET /pending` to read the workflow status.

Response:

```json
{
  "requestId": "8b583ebd-1f8f-46fa-b31b-06643f58d457",
  "status": "prepared",
  "confirmedTxs": [
    {
      "id": "approve-direct-resolution-fee",
      "hash": "0xdddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd"
    },
    {
      "id": "pay-direct-market-fee-1",
      "hash": "0x7777777777777777777777777777777777777777777777777777777777777777"
    },
    {
      "id": "initialize-market-1",
      "hash": "0xeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee"
    }
  ]
}
```
