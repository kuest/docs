## Step 1: Site + Wallet

<AccordionGroup>
  <Accordion title="Site name" icon="type" defaultOpen>
    Use the public name users should see on the site.
  </Accordion>
  <Accordion title="Admin wallet" icon="wallet">
    Connect the wallet that should become the first admin. One signature creates the Kuest credentials used by the site.
  </Accordion>
  <Accordion title="Email" icon="mail">
    Enter the required contact email before connecting and signing with the admin wallet.
  </Accordion>
</AccordionGroup>

<Info>
This signature does not move funds and the wallet does not need a balance. The connected address becomes the first admin wallet.
</Info>

## Step 2: Connections

<AccordionGroup>
  <Accordion title="GitHub" icon="github" defaultOpen>
    Connect the account or organization where the project repository should live.
  </Accordion>
  <Accordion title="Vercel" icon="key-round">
    Paste a Vercel token and let the form verify it, or use the account connection option when available. Get a token from [vercel.com/account/tokens](https://vercel.com/account/tokens) with access to the account or team that will own the deployment.
  </Accordion>
  <Accordion title="Connect Vercel to GitHub" icon="link">
    If prompted, allow Vercel to import the repository from your GitHub account.
  </Accordion>
  <Accordion title="Reown Project ID" icon="wallet-cards">
    Paste the project ID used for wallet login. Get it from [cloud.reown.com](https://cloud.reown.com).
  </Accordion>
  <Accordion title="Supabase database" icon="database">
    If prompted, select **Set up Supabase in Vercel**, complete the Marketplace integration, then refresh the database list. Choose **CREATE NEW DATABASE** for an isolated production database. Reuse an existing project only when the environments are intentionally shared.
  </Accordion>
</AccordionGroup>

### Advanced options

<AccordionGroup>
  <Accordion title="Project slug override" icon="pen">
    Use it only if you want a different project slug or final URL name.
  </Accordion>
  <Accordion title="Repository" icon="folder-git-2">
    Use the `owner/repo` format. This is usually filled automatically after GitHub is connected.
  </Accordion>
  <Accordion title="Branch" icon="git-branch">
    Keep `main` unless your production branch uses a different name.
  </Accordion>
  <Accordion title="Vercel Team ID" icon="building-2">
    Leave it empty for a personal Vercel account. Fill it only for team-owned projects.
  </Accordion>
  <Accordion title="Vercel region" icon="map-pinned">
    Choose the region for the application's server functions. Keep it close to the Supabase database region.
  </Accordion>
  <Accordion title="Supabase region" icon="map-pinned">
    Usually the default is fine. Change it only if you want a different region.
  </Accordion>
  <Accordion title="BETTER_AUTH_SECRET" icon="shield-check">
    You can leave it empty and let the setup generate one automatically.
  </Accordion>
  <Accordion title="CRON_SECRET" icon="timer">
    You can leave it empty and let the setup generate one automatically.
  </Accordion>
  <Accordion title="SITE_URL override" icon="globe">
    Fill it only if you already know the final public URL you want to use.
  </Accordion>
  <Accordion title="Extra env vars" icon="plus">
    Use one `KEY=value` per line for optional services or runtime overrides.
  </Accordion>
</AccordionGroup>

<Info>
Helpful pages: [Environment Variables](/configuration/environment-variables) and [Vercel + Supabase](/manual-installation/vercel).
</Info>

## Step 3: Deploy

<AccordionGroup>
  <Accordion title="Deploy button" icon="rocket" defaultOpen>
    Starts the launch with your site name, repository, branch, database choice, and environment values.
  </Accordion>
  <Accordion title="Timeline" icon="list-todo">
    Follow credential validation, repository setup, database connection, and deployment progress. If a stage fails, open its logs before retrying.
  </Accordion>
  <Accordion title="Result panel" icon="panel-top">
    Shows the deployment result and final setup checklist, including an optional custom domain and the required Reown allowed-domain step.
  </Accordion>
</AccordionGroup>

<Info>
After install, go to [General](/admin/general) to set your brand, support link, fee wallet, and core settings.
</Info>

## Verify the launch

<Steps>
  <Step title="Finish domain setup">
    Optionally add your site domain in the result panel, apply the DNS records it shows, and verify it. You can also continue with the temporary Vercel domain. Follow [Custom Domain](/configuration/custom-domain#site-domain) to set the canonical `SITE_URL` and redeploy when changing domains.
  </Step>
  <Step title="Allow the site in Reown">
    Open your Reown project, go to **Configuration → Allowed Domains**, add the final site URL shown in the result panel, and save. Confirm the step in the launch form after saving in Reown.
  </Step>
  <Step title="Open the project URL">
    Wait for the Vercel deployment to become ready, then confirm the home page loads from the final site URL.
  </Step>
  <Step title="Connect the admin wallet">
    Sign in with the wallet from Step 1 and confirm the admin dashboard is available.
  </Step>
  <Step title="Complete the operator setup">
    Configure [General settings](/admin/general) and [Integrations](/admin/integrations), then verify [scheduled jobs](/manual-installation/scheduler-jobs) before sending traffic to the site. Branded [service subdomains](/configuration/custom-domain#service-subdomains) are optional.
  </Step>
</Steps>
